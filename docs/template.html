Go-live readiness check

Before a hospital unit goes live on a new staffing system, three feeds have to agree: the staff roster from HR, the schedule and pay codes from timekeeping, and the hourly patient census from the EHR. This tool reads all three and says, unit by unit, whether the unit is ready, and which team has to fix what.

How to read this page
  1. Pick First data pull to see a made-up two-hospital system with 25 typical data problems planted in it, or After fixes to see the same system once those problems are fixed.
  2. Each unit card shows its verdict. NO-GO means at least one blocking problem. GO WITH FIXES means only warnings. GO means nothing found.
  3. Click a unit to see its problems, or read the fix list below, which is grouped by the team that owns each fix.

How well the checks catch problems

Each of the 25 planted problems was run on its own and all together. A false positive is a problem the tool reports that was not planted.

    Run it yourself

    Python 3.9 or later, standard library only. From the repo folder:

    python3 -m readiness.report sample_data/first_pull
python3 -m readiness.report sample_data/after_fixes
python3 -m eval.run_eval
python3 -m unittest
